# 메인 푸터 네이티브 개편 체크리스트

> 대상: `front/view/frame/mainFooter.jsx`, 스타일 `front/styles/frame.style.js`의 `createFooterStyles`.  
> 탭 전환은 지금처럼 `MainTabNavigator`의 `navigation.navigate`다. 네이티브는 재질과 pill 위치만 그린다.  
> iOS와 Android는 따로 구현한다. 한쪽이 끝나기 전에 다른 쪽 파일을 만들지 않는다.  
> prebuild와 개발 클라이언트 재빌드는 하지 않는다.  
> iOS 3단계(iOS만 `MainFooterIOS`)까지 반영했다. Android 네이티브 탭바는 아직이다.

지금 푸터에 넘어오는 값은 `activeTab`과 `onTabPress`다. 스케치의 `state` / `navigation` / `tabs`로 바꾸지 않는다. `activeIndex`는 `activeTab`에서 계산한다.

`MainScreen`의 `SafeAreaView`는 이미 `edges={['top', 'bottom']}`이다. 유리 바의 `bottom: insets.bottom`을 그대로 더하면 홈 인디케이터 위로 한 번 더 뜬다. iOS 적용 때 그 간격을 보고, 콘텐츠와 겹치면 inset을 빼거나 탭 바를 safe area 밖으로 낸다.

플로팅 버튼의 `aboveFooter`는 지금 푸터 높이 `FOOTER_HEIGHT`(65)를 더한다. 유리 바가 떠도 그 계산은 이번 범위가 아니다.

## iOS

유리 재질만 `expo-glass-effect`다. pill 이동과 탭 누르기는 React Native에 둔다. iOS 26 미만은 지금 흰 `MainFooter`를 그대로 그린다.

### 0. 작업 순서

- [x] 1단계: `expo-glass-effect`를 설치한다. prebuild는 하지 않는다
- [x] 2단계: `MainFooterIOS.jsx`를 만든다. 아이콘·라벨은 지금 `mainFooter.jsx`와 같다
- [x] 3단계: `mainFooter.jsx`에서 iOS만 `MainFooterIOS`로 보낸다. 그 외 플랫폼의 그리기 코드는 그대로 둔다

### 1. 설치

- [x] `npx expo install expo-glass-effect`
- [x] `ios/` 생성, prebuild, 개발 클라이언트 재빌드는 하지 않는다
- [x] 지금 바이너리에 유리 뷰가 없으면 `isLiquidGlassAvailable()`이 false라 기존 푸터가 나온다

### 2. `MainFooterIOS.jsx`

경로: `front/view/frame/MainFooterIOS.jsx`.

- [x] `GlassView`, `isLiquidGlassAvailable`는 `expo-glass-effect`에서 가져온다
- [x] `isLiquidGlassAvailable()`이 false면 지금 `MainFooter` 그리기를 그대로 반환한다. 아이콘·라벨·삼각형 인디케이터를 다시 짜지 않는다
- [x] true일 때만 `GlassView`로 감싼다. `glassEffectStyle="regular"`, `isInteractive`
- [x] 컨테이너: `position: 'absolute'`, `left: 10`, `right: 10`, `bottom: 10`. `MainScreen`이 하단 safe area를 이미 적용해서 `insets.bottom`은 더하지 않는다. `borderRadius: 26`, `flexDirection: 'row'`, `padding: 6`
- [x] `onLayout`으로 가로 너비를 탭 수(5)로 나눠 `tabWidth`를 구한다
- [x] pill은 `GlassView` 안쪽의 `Animated.View`다. `translateX`는 `withSpring(activeIndex * tabWidth, { damping: 18 })`
- [x] pill 크기: 너비 `tabWidth - 8`, `borderRadius: 20`, 배경 `colors.primary`. 위아래는 패딩 6에 맞춘다
- [x] 아이콘·라벨 `TouchableOpacity` 다섯 개는 지금 순서와 같다. 누르면 기존 `onTabPress(tab)`
- [x] 선택 탭 글자·아이콘색은 지금처럼 `colors.primary`, 나머지는 `colors.textLight4`
- [x] 유리 모드에서는 흰 배경과 삼각형 `activeTabIndicator`를 그리지 않는다

### 3. 분기

- [x] `Platform.OS === 'ios'`일 때만 `MainFooterIOS`를 반환한다
- [x] Android와 그 외는 지금 `mainFooter.jsx`의 `View` + `TouchableOpacity`를 유지한다
- [x] `MainTabNavigator`의 `tabBar`, `navigation.navigate`는 수정하지 않는다

## Android

Compose로 pill 자리만 그린다. 탭 누르기와 아이콘은 React Native다. 구조는 `modules/youth-paper-widget`과 같은 로컬 Expo 모듈이다.

### 0. 작업 순서

- [ ] 1단계: `modules/youth-paper-tabbar-chrome` 스캐폴드를 만든다. prebuild는 하지 않는다
- [ ] 2단계: Android에 `TabBarChromeView`와 `TabBarChromeModule`만 채운다. iOS 네이티브 파일은 만들지 않는다
- [ ] 3단계: `MainFooterAndroid.jsx`에서 네이티브 뷰 뒤에 기존 아이콘·라벨을 올린다
- [ ] 4단계: `mainFooter.jsx`에서 Android만 `MainFooterAndroid`로 보낸다

### 1. 모듈

- [ ] `npx create-expo-module --local youth-paper-tabbar-chrome`
- [ ] `front/package.json`에 `youth-paper-widget`처럼 `file:modules/youth-paper-tabbar-chrome`을 넣는다
- [ ] `expo-module.config.json`의 Android 모듈 이름은 뷰 모듈과 맞춘다. iOS 모듈 목록은 비운다
- [ ] `app.config.js` plugins에 위젯과 같은 방식으로 등록이 필요하면 그때만 추가한다. prebuild는 하지 않는다
- [ ] 네이티브 뷰가 없는 바이너리에서는 지금 `MainFooter`를 그린다. `requireNativeViewManager` 실패로 탭이 죽으면 안 된다

### 2. `TabBarChromeView`

경로는 생성된 모듈의 `android/src/main/java/.../TabBarChromeView.kt`.

- [ ] `ExpoView` 안에 `ComposeView`를 넣는다
- [ ] 배경은 흰색. pill은 `animateDpAsState`로 `selectedIndex`에 따라 이동한다
- [ ] pill 크기 `56.dp` × `32.dp`, 모서리 `16.dp`, 색 `#E4F4DF` (`colors.primaryLight4`)
- [ ] `setSelectedIndex`, `setTabCount`만 둔다. 탭 클릭 콜백은 만들지 않는다

### 3. `TabBarChromeModule`

- [ ] 이름 `"TabBarChrome"`
- [ ] Prop `selectedIndex`, `tabCount`만 등록한다
- [ ] `OnViewDidUpdateProps`나 탭 이벤트는 없다

### 4. `MainFooterAndroid.jsx`

경로: `front/view/frame/MainFooterAndroid.jsx`.

- [ ] `requireNativeViewManager('TabBarChrome')`는 모듈이 있을 때만 쓴다
- [ ] 바깥 높이는 `FOOTER_HEIGHT`를 `normalize`한 값
- [ ] 네이티브 뷰는 `StyleSheet.absoluteFill`, `selectedIndex`는 `activeTab`의 인덱스, `tabCount`는 5
- [ ] 그 위 가로 `View`에 지금 아이콘·라벨 `TouchableOpacity`를 그대로 둔다. `onPress`는 `onTabPress(tab)`
- [ ] 삼각형 `activeTabIndicator`는 네이티브 pill이 대신하므로 그리지 않는다

### 5. 분기

- [ ] `Platform.OS === 'android'`일 때만 `MainFooterAndroid`를 반환한다
- [ ] iOS 분기가 이미 있으면 순서는 iOS, Android, 그 외 기존 푸터다
- [ ] `MainTabNavigator`의 `navigation.navigate`는 수정하지 않는다
