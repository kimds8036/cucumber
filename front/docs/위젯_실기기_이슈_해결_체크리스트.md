# 위젯 실기기 이슈 해결 체크리스트

> 작성: 2026-08-03  
> 전제: 실기기 빌드·위젯 표시까지는 확인됨. 아래 2건은 **기능 버그**.

## 재현된 문제

| # | 증상 | 기대 |
|---|------|------|
| 1 | 시간표를 앱에서 설정해도 위젯이 **「시간표를 설정해주세요」** 유지 | 저장/hydrate된 시간표가 Medium·Large에 표시 |
| 2 | 급식·시간표 위젯 탭 시 앱만 열리고 **학교 탭 / 마이페이지로 안 이동** | 급식 → 우리학교(`school`), 시간표 → 마이페이지(`mypage`) |

## 0. 원인 요약 (조사 결과)

### 문제 1 — 시간표 위젯이 항상 empty

**1순위 원인: Native `YouthPaperWidget` 모듈이 iOS 빌드에 안 들어감 → JS write가 silent no-op**

- `front/modules/youth-paper-widget/` 에 Swift 구현은 있으나 **`.podspec` 없음**
- Expo Apple autolinking은 podspec이 없으면 모듈을 `null`로 버리고 Pods에 포함하지 않음  
  (`expo-modules-autolinking` → `resolveModuleAsync`가 podspec 없으면 return null)
- 확인: `npx expo-modules-autolinking resolve --platform ios` 결과에 `youth-paper-widget` **미포함**
- JS는 `require('youth-paper-widget')`로 **stub**을 받고, native가 없어도 `noop()` 후 성공한 것처럼 보임  
  → App Group `UserDefaults`에 `timetable_widget_payload`가 **기록되지 않음**
- 위젯은 payload `nil` / empty → 「시간표를 설정해주세요」

앱 쪽 write 훅·flat 변환·App Group ID 문자열은 정상으로 보이며, **주원인은 브리지 미링크**.

**2순위:** App Group 프로비저닝 불일치 시 `UserDefaults(suiteName:)` write가 조용히 실패 (`defaults?.set`)

**낮은 가능성:** flat key/`empty` 로직 버그 (단위 테스트·키 형식 `"월-1"` 일치)

### 문제 2 — 딥링크가 탭으로 안 감

**앱은 열림** → scheme `youthpaper` / `RCTLinkingManager` 는 동작.

**1순위:** `MainScreen`이 탭 네비게이터를 **180ms 뒤에야 마운트** (`screenReady`)  
→ Linking이 먼저 `Main → school|mypage` state를 만들어도, 탭이 나중에 `initialRouteName="board"`로 뜨면 덮어씀

**2순위:** `authHydrated` 전 `RootNavigator`가 `null` → cold start 시 initial URL이 소비되고 Main/탭이 늦게 생김

**3순위:** Linking config는 nested path(`school`/`mypage`)인데, 탭 전환 보강은 `route.params.initialTab`만 처리 → linking state와 params 경로가 어긋나면 폴백 없음

위젯 URL 자체는 맞음: `youthpaper://school`, `youthpaper://mypage`

## 1. 문제 1 해결 체크리스트 (시간표 payload write)

### 1-1. Native 모듈을 iOS에 실제로 링크

- [ ] `front/modules/youth-paper-widget/ios/YouthPaperWidget.podspec` 추가  
  (Expo module 표준: `s.source_files`, `s.dependency 'ExpoModulesCore'`, `s.static_framework = true` 등)
- [ ] `package.json` / `expo-module.config.json` / podspec 이름·모듈명 `YouthPaperWidget` 일치 확인
- [ ] `cd front/ios && pod install` (또는 `npx pod-install`)
- [ ] `npx expo-modules-autolinking resolve --platform ios` 출력에 **`youth-paper-widget` / `YouthPaperWidget` 포함** 확인
- [ ] Xcode → Pods / YouthPaper 타겟에 모듈 소스가 컴파일되는지 확인
- [ ] 실기기 재빌드 (Clean Build 권장)

### 1-2. JS 브리지 no-op 감지 강화

- [ ] `requireNativeModule('YouthPaperWidget')` 실패 시 `widgetBridge`가 **성공(`true`)을 반환하지 않도록** 수정
- [ ] `__DEV__`에서 `writeTimetablePayload` / `writeMealPayload` 실패·스킵을 **눈에 띄게 로그**
- [ ] (선택) 네이티브 미연결이면 Toast/Alert로 개발 중 알림

### 1-3. App Group 실기록 검증

- [ ] 앱·위젯 entitlements 모두 `group.com.ucost.YouthPaper` (이미 소스상 일치)
- [ ] Developer Portal / Xcode Signing에서 **앱·위젯 확장 둘 다** 동일 App Group 체크
- [ ] 마이페이지 시간표 hydrate/저장 후 App Group에 `timetable_widget_payload` 키 존재 확인  
  (Xcode → Devices → Container / 또는 임시 native `NSLog` of read-back)
- [ ] `WidgetSharedStore.write` 실패 시 로그 (`UserDefaults(suiteName:)` nil 여부)
- [ ] write 후 `WidgetCenter.shared.reloadAllTimelines()` 호출 확인 (`reloadWidgets`)

### 1-4. Write 훅 동작 재확인 (모듈 링크 후)

- [ ] `mypage.jsx` hydrate → `syncTimetableWidgetFromFlat`
- [ ] `timetabelChoice` / `edittimetable` / `TimetableScreen` 저장 → sync
- [ ] 저장 직후 위젯 새로고침(홈 화면 복귀 또는 위젯 제거 후 재추가)으로 Medium/Large에 과목 표시
- [ ] (참고) 급식 위젯도 「급식 정보 없음」이면 **동일 write 경로 실패**로 같이 검증

### 1-5. DoD (문제 1)

- [ ] 시간표 설정/편집 후 위젯에 즉시(또는 reload 후) 데이터 표시
- [ ] 앱 재실행 없이 홈으로 나갔다 와도 payload 유지
- [ ] Metro/Xcode에 native unavailable skip 로그가 **더 이상 없음**

## 2. 문제 2 해결 체크리스트 (위젯 탭 → 탭 이동)

### 2-1. Main 탭 지연 마운트 수정

- [ ] `MainScreen.jsx`의 `screenReady` 180ms 지연 제거 **또는**
- [ ] `route.params.initialTab` / `route.params.screen` / pending deep link가 있으면 **즉시** `MainTabNavigator` 마운트
- [ ] 탭 `initialRouteName`이 딥링크 대상과 충돌하지 않게 처리

### 2-2. Auth hydrate 이후 URL 재적용

- [ ] `authHydrated === true` 이고 `Main`이 마운트된 뒤 `Linking.getInitialURL()` 재처리
- [ ] foreground `Linking.addEventListener('url')`도 동일 핸들러로 `school` / `mypage` 이동
- [ ] 로그인·학생증 게이트 통과 전 URL은 pending에 저장했다가 Main 진입 시 소비

### 2-3. 명시적 딥링크 → navigate 폴백

- [ ] `navigationRef`로 `youthpaper://school` →  
  `navigate('Main', { screen: 'school' })` 또는 `{ initialTab: 'school' }`
- [ ] `youthpaper://mypage` → `navigate('Main', { screen: 'mypage' })` / `{ initialTab: 'mypage' }`
- [ ] `App.js` linking config와 `MainTabNavigator`의 `initialTab`/`screen` 처리가 **같은 경로**를 쓰도록 통일
- [ ] (선택) path를 `youthpaper:///school` 형태로 통일해 파싱 모호성 제거

### 2-4. 위젯 쪽 URL (이미 맞음 — 회귀만 확인)

- [ ] Meal: `youthpaper://school`
- [ ] Timetable: `youthpaper://mypage`
- [ ] iOS `Info.plist` / `scheme: 'youthpaper'` 유지
- [ ] Android Glance intent도 동일 URI (Android 검증 시)

### 2-5. 수동 검증

- [ ] Safari 또는 `xcrun simctl openurl` / 기기 Notes 링크로  
  `youthpaper://school` → 우리학교 탭  
  `youthpaper://mypage` → 마이페이지 탭
- [ ] **Cold start** (앱 강제 종료 후 위젯 탭)
- [ ] **Warm start** (백그라운드에 앱 있는 상태로 위젯 탭)
- [ ] 위젯에서 탭했을 때도 동일

### 2-6. DoD (문제 2)

- [ ] 급식 위젯 탭 → 우리학교 화면
- [ ] 시간표 위젯(데이터 있음/없음 모두) 탭 → 마이페이지
- [ ] Cold/Warm 모두 통과

## 5. 이 체크리스트로 하지 말 것

- 급식 끼니 컷오프 / NEIS / JWT 풀스택을 위젯에 다시 구현하지 않음
- 시간표 SSOT를 NEIS 원본으로 바꾸지 않음 (로컬 캐시 미러 유지)
- 기존 급식·시간표 API 로직 리팩터 금지 — **브리지 링크·딥링크 라우팅만** 고침
