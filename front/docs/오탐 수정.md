## 2. 온라인 판정 규칙 (유지 + 보완)

현재 `isOnlineFromState` 의미를 유지하되, **적용 타이밍**만 바꾼다.

| 신호 | 처리 |
|------|------|
| `state` 없음 | online (기존과 동일) |
| `isConnected === false` | **즉시** offline (디바운스 없음) |
| `isInternetReachable === false` (그리고 connected가 false가 아님) | **즉시 offline 확정 금지** → 약 **2초 디바운스** 후 여전히 해당 상태면 offline |
| 그 외 (`reachable === true` / `null` 등) | online. 진행 중인 reachable-false 디바운스 타이머 **취소** |

체크:

- [ ] `isConnected === false` → 디바운스 없이 `setOnline(false)`
- [ ] `isInternetReachable === false`만으로 즉시 `setOnline(false)` 하지 않음
- [ ] reachable-false 디바운스 중 online 신호가 오면 타이머 취소 + online 유지/복구
- [ ] 디바운스 만료 시점에 한 번 더 상태를 확인해 offline 확정 (중간에 online 왔으면 확정하지 않음)

## 3. 디바운스 (요구사항 1·2)

권장 상수:

```text
REACHABLE_FALSE_DEBOUNCE_MS = 2000
```

- [ ] reachable-false 전용 타이머 ref 추가 (예: `reachableFalseTimerRef`)
- [ ] 동일 신호가 연속으로 와도 타이머를 중복 생성하지 않음 (이미 대기 중이면 재시작 여부 정책 명확히: **재시작 또는 유지 중 하나** — 권장: **이미 대기 중이면 유지**, 첫 false부터 2초 측정)
- [ ] online / connected 복구 시 타이머 `clearTimeout` + ref null
- [ ] unmount 시 타이머 cleanup

**왜 2초:** 백그라운드→포그라운드 복귀 직후 NetInfo reachability 재검사가 보통 수백 ms~1초대에서 끝나며, 2초면 일시 false를 걸러내면서도 진짜 오프라인일 때 과도하게 늦게 뜨지 않는 균형.

---

## 4. AppState 포그라운드 복귀 (요구사항 3)

권장 상수:

```text
FOREGROUND_GRACE_MS = 1000
```

- [ ] `AppState` import 및 `addEventListener('change', …)` 등록
- [ ] `background|inactive` → `active` 전환만 처리
- [ ] 전환 직후: NetInfo 리스너 결과를 **바로 신뢰하지 않음**
  - 구현 예: `ignoreNetInfoUntilRef = Date.now() + FOREGROUND_GRACE_MS`  
    또는 `isResumingRef = true` 후 1초 뒤 false
- [ ] grace 동안 들어온 NetInfo 이벤트는 offline 확정에 쓰지 않음 (또는 apply 스킵)
- [ ] grace 종료 후 `NetInfo.fetch()`로 **명시 재검사** → 그 결과로 `apply` (reachable-false면 디바운스 규칙 적용)
- [ ] unmount 시 AppState subscription 해제 + grace 타이머 cleanup

**왜 1초:** OS/NetInfo가 복귀 직후 한 번 흔들린 뒤 안정화되는 짧은 구간. 너무 길면 진짜 오프라인 감지 지연, 너무 짧으면 오탐이 남음.

## 5. `refresh()` / 레이스 정리 (요구사항 4)

- [ ] 「다시 시도」 `refresh()`는 UI에서 그대로 호출 가능
- [ ] `refresh()`는 `NetInfo.fetch()` 후 최신 상태로 판정 (기존과 동일 목적)
- [ ] `refresh()` 호출 시:
  - [ ] reachable-false 디바운스 타이머 취소
  - [ ] (선택) resume grace를 깨고 즉시 fetch 결과를 신뢰 — **다시 시도는 사용자 의도이므로 즉시 반영 권장**
- [ ] resume 재검사 / listener / refresh가 동시에 돌아도 **마지막 fetch 결과만 반영**되도록 (예: 요청 세대 번호 `fetchGenRef` 또는 “완료 시점에만 apply”)
- [ ] NetInfo 초기화 실패 시 기존처럼 `setOnline(true)` 유지
