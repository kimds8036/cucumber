# 레이아웃 개편 체크리스트

> 기준: 프레임 폭 375, `normalize(n) = round((width / 375) × n)`, 화면 좌우 거터는 전부 `width * 0.04`.  
> 3단계(`boardAll` 상쇄 마진)까지 반영했다. 가입 거터는 아직 그대로다.  
> 375 기준의 4%는 15px이다. `normalize(15)`와 같다.  
> **가입 단계(`front/view/src/signup/`, `signupEntry.style.js`)는 계획을 유지하지만 이번 수정에서는 건너뛴다.**

---

## 0. 이번 수정 순서

- [x] 1단계: `normalize` 정의가 위 식과 같은지 확인하고, 다른 식만 고친다
- [x] 2단계: 가입 단계를 제외한 화면 가장자리 거터를 `width * 0.04`로 통일한다
- [x] 3단계: 가입이 아닌 화면의 `-width * 0.04` 상쇄 마진만 정리한다 (`boardAll.jsx`)
- [ ] 가입 단계 거터·상쇄 마진은 아래 「나중」 목록 그대로 두고 이번엔 수정하지 않는다

## 1. normalize

목표 식:

```text
normalize(n) = Math.round((width / 375) * n)
```

현재 `getNormalize`와 화면 안의 `const scale = width / 375`는 이미 이 식이다. 스타일 팩토리와 화면 로컬 함수가 같은 구현을 복사해 두고 있다.

- [x] `width / 375`가 아닌 기준 폭이 있으면 375로 고친다. `ad.style.js` 폴백 폭 360만 375로 바꿨다
- [x] `Math.round`가 빠진 `normalize`가 있으면 반올림을 넣는다. 시간표 정적 스타일과, normalize를 안 넘겼을 때의 폴백만 식을 따르지 않아 고쳤다
- [x] 식은 유지한다. 함수를 한 파일로 합치는 작업은 이번 범위가 아니다

글자 크기(`fontSizes`)도 이 `normalize`를 통과한다. 기준 폭만 같고, 거터 4%와는 별개다.

---

## 2. 무엇을 고치고, 무엇을 그대로 두나

고치는 것은 **화면 좌우 가장자리에서 본문까지 띄우는 거터**뿐이다. 375px 화면에서 그 여백은 15px이다.

```text
|← 4% →|  본문 열  |← 4% →|
|  15   |   345    |  15   |   합 375
```

아래 항목은 거터가 아니다. **이번에도, 나중 가입 수정에서도 4%로 바꾸지 않는다.**

### 버튼·칩·인풋 안쪽 패딩 — 수정하지 않음

컨트롤 테두리와 글자 사이의 여백이다. 화면 가장자리와 무관하다.

게시판 정렬 칩 (`board.style.js` `sortButton`):

```text
paddingHorizontal: normalize(16)   // 칩 안, 글자 좌우
paddingVertical: normalize(8)
```

이 16은 “375의 4%”가 아니라 “칩 디자인의 16”이다. 화면이 커지면 `normalize`가 같이 커진다. 이걸 `width * 0.04`로 바꾸면 칩 안 여백이 화면 너비의 4%(375에서 15px)에 고정되어, 칩이 화면 폭을 따라 불필요하게 넓어진다.

같은 이유로 남긴다.

- 버튼 안 `paddingHorizontal: normalize(n)`
- 인풋 안 글자 여백 (`bottomInput`의 `normalize(6)` 같은 값)
- 뱃지 안 패딩

인풋 **막대 전체**가 화면 좌우에 붙는 경우만 거터다. 예: 댓글 입력 줄 `bottomInputRow`의 `paddingHorizontal: width * 0.03`. 이것은 화면 가장자리 inset이라 4%로 바꾼다. 그 안의 글자 여백 `paddingHorizontal: normalize(4)`는 그대로 둔다.

### 카드 간격 — 수정하지 않음

카드와 카드 사이, 카드 테두리와 카드 글자 사이는 거터가 아니다.

게시글 카드 (`board.style.js`):

```text
postList     paddingHorizontal: width * 0.04   ← 거터. 이미 4%면 유지
postItem     padding: normalize(14)            ← 카드 안 여백. 유지
postItem     marginBottom: normalize(12)       ← 카드 사이 간격. 유지
```

`postList`가 좌우 4%를 이미 띄우므로, 카드 안 14px까지 4%로 바꾸면 글자가 카드 테두리에서 한 번 더 15px 들어간다. 카드가 더 답답해질 뿐 화면 거터는 달라지지 않는다.

`gap: normalize(8)`처럼 칩과 칩 사이 간격도 같은 이유로 유지한다. `frame.style.js`의 `gap: width * 0.03`은 헤더 아이콘 사이 간격이라 화면 거터가 아니다. 유지한다.

### 이미지·말풍선 비율 — 수정하지 않음

`width * 0.68`은 여백이 아니라 **그 요소의 너비**다. 학생증 프리뷰가 화면의 68%라는 뜻이다. 4%로 바꾸면 가로가 15px로 줄어든다.

말풍선 (`message.style.js` `opponentBubble`):

```text
paddingHorizontal: normalize(12)   ← 말풍선 안 글자 여백. 유지
maxWidth: '75%'                    ← 말풍선이 가로의 75%를 넘지 않음. 유지
```

메뉴·말풍선 `minWidth: width * 0.45`, `maxWidth: width * 0.7`도 크기 제한이다. 거터가 아니므로 유지한다.

`width * 0.92`만 예외로 보이지만, 이것은 “화면에서 좌우 4%를 뺀 본문 폭”이다. 거터를 4%로 유지하는 화면에서는 그대로 둔다. 7% 거터를 가정한 `width * 0.14`(7%×2)는 가입 달력에만 있고, 이번 수정에서는 건드리지 않는다.
