## 1. 공지사항 — 관리자 작성 → 앱 연동

### 목표
관리자 페이지에서 공지를 게시하면 앱 **고객지원 → 공지사항** 목록·상세에 바로 보이게 한다.

### 이미 있는 것 (재구현 불필요)

| 층 | 경로·내용 |
|----|-----------|
| DB | `008_announcements.sql` — `announcements` (`draft` / `published`) |
| Admin UI | 사이드바「공지사항」, `back/admin/assets/js/13-announcements.js` |
| Admin API | `/api/admin/announcements` CRUD |
| Public API | `GET /api/announcements`, `GET /api/announcements/:id` (게시된 것만) |
| 앱 | `announcement.jsx`, `AnnouncementDetail.jsx`, `info.jsx` 진입 |

### 오늘 할 일 (검증 → 갭만 수정)

1. **E2E 스모크**
   - develop 관리자에서 공지 **초안 저장** → 앱에 안 나오는지
   - **게시** → 앱 목록·상세에 제목·본문·날짜 표시
   - 수정·삭제 후 앱 새로고침(포커스) 반영
2. **환경 확인**
   - develop Railway에 `008` migrate 적용 여부
   - 앱이 develop API를 치는지 (`APP_ENV` / `EXPO_PUBLIC_API_URL`)
3. **갭이 보이면만 수정** (예상 후보)
   - 본문 마크다운/줄바꿈 렌더 깨짐
   - 목록 캐시·포커스 미갱신
   - 게시 시 푸시/인앱 알림이 **필요하면** 별도 범위로 잡기 (지금은 설정 토글 `announcement`만 있고 자동 발송은 없는 것으로 보임)

### 완료 기준
- [ ] 관리자「게시」한 공지가 develop 앱 공지 목록에 표시
- [ ] 상세 진입·뒤로가기·당겨서 새로고침 정상
- [ ] 초안은 앱에 노출되지 않음

### 범위 밖 (오늘 안 함, 합의 시)
- 공지 게시 시 FCM 일괄 발송
- 홈/게시판 상단 공지 배너 (팁·고정과 별개)

## 2. 인앱 팁 — 관리자 관리 + 게시판 상단 고정

### 목표
1. 관리자가 팁 문구를 CRUD 한다.  
2. **중요한 팁은 고정**해서 메인 게시판 최상단 팁 영역에 우선 노출한다.  
3. 고정이 없으면 기존처럼 랜덤(또는 순환) 팁을 보여 준다.

### 이미 있는 것

| 층 | 경로·내용 |
|----|-----------|
| 상수 | `front/constants/tipMessages.js` (~18개 하드코딩) |
| UI | `TipPlaceholder`, `TopAdBanner`, `AdOrTip` |
| 게시판 | `boardAll.jsx` ListHeader — 광고 없으면 tip |

### 없는 것
- tips 테이블 / Public·Admin API / 관리자 패널

### 제안 설계

```text
관리자「인앱 팁」패널
  → tips 테이블 CRUD
  → is_pinned / pin_priority / active

앱 게시판 상단 TopAdBanner
  → GET /api/tips (또는 /api/tips/active)
  → pinned 있으면 그 문구(들) 고정 표시
  → 없으면 active 풀에서 랜덤 (기존 UX 유지)
  → 광고 정책과 충돌 시: 광고 우선 vs 고정 팁 우선 — 아래 결정 필요
```

#### DB (초안)

```sql
tips (
  id,
  body           VARCHAR(...),   -- 팁 문구
  status         ENUM('draft','active'),
  is_pinned      TINYINT(1) DEFAULT 0,
  pin_priority   INT DEFAULT 0,  -- 높을수록 우선 (고정 여러 개일 때)
  starts_at      DATETIME NULL,  -- 선택: 기간 노출
  ends_at        DATETIME NULL,
  created_by_admin_id,
  updated_by_admin_id,
  created_at, updated_at
)
```

#### API
- Admin: `GET/POST/PATCH/DELETE /api/admin/tips`
- Public: `GET /api/tips` → `{ pinned: Tip|null, items: Tip[] }`  
  (또는 `pinned[]` + `pool[]`)

#### 앱 동작
- `tipMessages.js`는 **폴백**으로만 유지 (API 실패·빈 목록 시)
- `TopAdBanner` / `TipPlaceholder`: 서버 데이터 우선
- 고정 팁: 새로고침해도 동일 문구 유지 (랜덤 키와 분리)
- 고정 해제 시 다시 풀 랜덤

#### 관리자 UI
- 사이드바「인앱 팁」패널 (공지 `13-announcements.js` 패턴 복제)
- 목록 · 작성 · 활성/비활성 · **고정 토글** (고정은 1개만? / 여러 개 롤링?)

### 오늘 결정이 필요한 것 (계획 리뷰 때)

| 질문 | 옵션 A | 옵션 B (권장 초안) |
|------|--------|-------------------|
| 고정 개수 | 여러 개 순환 | **항상 1개만** 고정 (단순) |
| 광고와의 관계 | 광고 있으면 팁 숨김 (현행) | **고정 팁은 광고보다 우선** |
| 노출 위치 | 게시판 상단만 | 상단 + 기존 tip 자리 전부 서버화 |
| 기간 설정 | 없음 | starts_at / ends_at |

**권장:** 고정 1개 · 게시판 상단부터 · 광고 있을 때는 기존처럼 광고 우선(고정 팁은 광고 없을 때만). 원하면「고정은 광고 위에도」로 바꿀 수 있음.

### 작업 순서
1. migration + service + admin/public routes  
2. admin UI 패널  
3. 앱: tips fetch 훅/유틸 + `TopAdBanner` / board 연동  
4. 폴백·빈 상태·고정 해제 E2E

### 완료 기준
- [ ] 관리자에서 팁 추가·수정·비활성
- [ ] 고정 ON → 메인 게시판 상단 팁이 해당 문구로 고정
- [ ] 고정 OFF → 풀에서 랜덤 (또는 폴백 상수)
- [ ] API 실패 시에도 앱이 깨지지 않음

## 3. 앱스토어 · 플레이스토어 리뷰 연동

### 목표
사용자가 앱 안에서 **스토어 리뷰를 남길 수 있게** 유도한다.  
(스토어 웹에 리뷰 목록을 긁어오는 연동이 아니라, **인앱 리뷰 요청 / 스토어 작성 화면 열기**)

### 이미 있는 것
- Play / App Store URL: `front/utils/shareLinks.js`, `back/src/utils/storeUrls.js`
- 강제 업데이트 시「스토어 열기」: `ForceUpdateGate`

### 없는 것
- `expo-store-review` / `StoreReview.requestReview()` 등
- 타이밍·쿨다운·「나중에」UX

### 제안 설계

```text
트리거 (예: 타이머 N회 완료 / 가입 N일 후 / 마이페이지「리뷰 남기기」)
  → 가능하면 StoreReview.requestReview()  (시스템 인앱 다이얼로그)
  → 불가·거절·미지원 시 Linking.openURL(스토어 리뷰 URL)
  → AsyncStorage로 쿨다운 (예: 90일) · 「다시 묻지 않음」
```

| 플랫폼 | 방식 |
|--------|------|
| Android | Play In-App Review (가능 시) → 실패 시 Play 스토어 URL |
| iOS | `SKStoreReviewController` via expo-store-review → 실패 시 App Store URL |

### 오늘 결정할 것

| 질문 | 권장 |
|------|------|
| 진입점 | **마이페이지 버튼** + (선택) 자동 프롬프트 1곳 |
| 자동 타이밍 | 성급하지 않게 — 예: 가입 3일+ & 타이머 사용 1회+ |
| 관리자 제어 | 1차는 **앱 상수/로컬 룰**만. 원격 on/off는 후순위 |

### 작업 순서
1. `expo-store-review` 추가, `requestAppReview()` 유틸 (`shareLinks` URL 재사용)  
2. 마이페이지「리뷰 작성하기」수동 진입  
3. (여유 있으면) 자동 프롬프트 + 쿨다운  
4. production/develop 스토어 URL·실기기 스모크 (시뮬레이터는 리뷰 UI 제한 있음)

### 완료 기준
- [ ] 마이페이지에서 리뷰 유도 → 시스템 시트 또는 스토어 페이지 오픈
- [ ] 같은 사용자가 짧은 간격에 반복 노출되지 않음 (쿨다운)
- [ ] URL/패키지 ID가 production 스토어와 일치

### 주의
- iOS/Android 모두 **OS가 실제 노출 여부를 제한**할 수 있음 → 수동「스토어에서 리뷰」폴백 필수
- Google/Apple 가이드: 리뷰 대가로 보상 금지
