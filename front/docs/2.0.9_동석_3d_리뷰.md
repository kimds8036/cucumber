## 1. [P0] 애니메이션 FBX에 모델이 매번 들어 있다 → 모델 1개 + 모션만 분리

지난번에 나온 개선안이 이것이다. 지금 구조와 바꿀 구조를 정리한다.

### 지금

```
CHA/boy/boy stay.fbx    15.9MB  ← 모델 + 뼈 + 텍스처 + stay 모션
CHA/boy/boy walk.fbx    15.8MB  ← 같은 모델 + 같은 텍스처 + walk 모션
CHA/boy/boy Run.fbx     15.8MB
CHA/boy/boy sit.fbx     15.9MB
CHA/boy/boy sit hi.fbx  16.0MB
CHA/boy/boy lay.fbx     16.1MB
CHA/GIRL/... 6개        각 12.7~13.5MB
합계 약 175MB (남 ≈ 95MB, 여 ≈ 78MB)
```

`loader.js`의 `loadCharacter()`는 6개를 `Promise.all`로 다 받고, 다 파싱한다. 그런데 실제로 쓰는 모델은 `stayFbx` 하나다. 나머지 5개는 `fbx.animations`에서 클립 하나만 꺼내고 버린다.

모션 데이터는 파일당 수백 KB 수준이다. 나머지는 거의 메시와 텍스처다. 파일마다 `anime_chibi_..._part_N_basecolor.PNG`가 들어 있다. 남자는 38장, 여자는 7장이다.

그래서 생기는 문제:

- **다운로드**: 남자 캐릭터 하나에 약 95MB. 모바일 데이터에서 입장이 수십 초 걸린다.
- **파싱**: `FBXLoader`는 메인 스레드에서 돈다. 같은 메시와 텍스처를 6번 디코딩한다. 그동안 화면이 멈춘다.
- **메모리**: 파싱된 메시·이미지 6벌이 잠깐 같이 올라간다. 저사양 안드로이드 WebView, iOS WKWebView에서 프로세스가 죽을 수 있다 (4번 항목과 이어짐).
- **성별이 섞이면 두 배**: 다른 성별 사람이 들어오면 `getTemplate()`이 반대 성별 6개를 또 받는다. 최대 175MB다.

### 바꿀 구조

```
CHA/boy/boy.glb          ← 모델 + 뼈 + 텍스처 (모션 없음, 또는 stay만)
CHA/girl/girl.glb
CHA/anim/anims.glb       ← 뼈 + 모션 클립 6개만 (메시·텍스처 없음)
                           stay, walk, run, sit, sitHi, lay
```

남녀가 같은 Mixamo 뼈 이름(`mixamorig:Hips` 등)이면 모션 파일 하나를 같이 쓴다. 뼈 비율이 달라서 어색하면 `anims_boy.glb`, `anims_girl.glb`로 나눈다. 그래도 모델은 성별당 1번만 받는다.

예상 크기 (확인 필요, 대략치):

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 남자 1명 입장 | ~95MB | 모델 GLB 10MB 안팎 + 모션 1~3MB |
| 텍스처 압축(WebP/KTX2)·메시 압축(Meshopt)까지 | | 수 MB 대 |

### 만드는 방법

**Mixamo에서 다시 받는 경우**

1. 모델은 지금처럼 `With Skin`으로 한 번만 받는다 (T-pose 또는 stay).
2. 모션 6개는 `Without Skin`으로 받는다. 뼈와 모션만 들어 있어서 파일이 작다.
3. Blender에서 모델 FBX를 연다. 모션 FBX들을 차례로 가져와 Action을 모델 Armature에 붙인다.
4. 각 Action 이름을 `stay`, `walk`, `run`, `sit`, `sitHi`, `lay`로 바꾼다. **이름 바꾸기는 꼭 해야 한다** (5번 항목).
5. NLA에 Action을 모두 push down 하고 `.glb`로 내보낸다. 모델 파일과 모션 파일을 따로 낼지, 하나로 낼지는 아래에서 고른다.

**지금 FBX만 있는 경우**

Blender에서 `boy stay.fbx`를 기준 모델로 연다. 나머지 5개를 가져와 Action만 남기고 메시·텍스처는 지운다. 그 뒤는 위 4~5번과 같다.

### 파일 하나로 묶기 vs 나누기

| | 모델+모션 한 파일 (`boy.glb`) | 모델·모션 분리 |
|---|---|---|
| 요청 수 | 1번 | 2번 |
| 남녀 모션 공유 | 안 됨 | 됨 |
| 모션만 고칠 때 | 모델까지 다시 받음 | 모션 파일만 바뀜 |

추천은 **분리**다. 성별 모델 2개 + 공용 모션 1개.

### 코드 변경

`loader.js`

- `FBXLoader` → `GLTFLoader` (+ `MeshoptDecoder`, 필요하면 `KTX2Loader`).
- `Promise.all([6개])` → `Promise.all([모델, 모션])`.
- 클립은 `gltf.animations`에서 **이름으로 정확히** 찾는다. 없으면 `clips[0]`으로 떨어지지 말고 `null`로 둔다.
- 모션 GLB의 뼈 이름과 모델 뼈 이름이 같아야 `AnimationMixer`가 붙는다. 다르면 `SkeletonUtils.retargetClip`이 필요하다. 처음부터 같은 Mixamo 뼈를 쓰는 게 가장 쉽다.
- `pinHips()`, `samplePose()` 보정 로직은 그대로 쓸 수 있다. 다만 트랙 이름이 FBX와 GLB에서 다르다. FBX는 `mixamorigHips.position`, GLB는 `mixamorig:Hips.position` 또는 Blender가 바꾼 이름이 된다. 정규식 `/hips\.position$/i`가 맞는지 첫 로드 때 로그로 확인한다.
- GLB에서 단위가 바뀌면(FBX cm → GLB m) `pinHips`의 `Math.abs(y1 - y0) > 8` 같은 임계값이 안 맞는다. `CHARACTER_HEIGHT`로 정규화한 뒤의 값으로 바꾸거나 단위를 확인한다.

`config.js`

```js
CHAR: {
  boy:  { model: "CHA/boy/boy.glb" },
  girl: { model: "CHA/girl/girl.glb" },
},
CHAR_ANIM_URL: "CHA/anim/anims.glb",
```

### 같이 하면 좋은 압축

```bash
npx @gltf-transform/cli optimize boy.glb boy.opt.glb --compress meshopt --texture-compress webp --texture-size 1024
```

- 남자 텍스처 38장은 Blender에서 **아틀라스 1~2장으로 합치는 게** 가장 효과가 크다. 7번 항목과 같이 본다.
- 치비 캐릭터를 화면에서 작게(키 0.6) 보므로 텍스처는 512~1024면 충분하다.

### 확인

- [ ] 남녀 모델 GLB, 모션 GLB 크기 기록
- [ ] 첫 입장 시간: 지금 vs 바꾼 뒤 (Wi-Fi, LTE 각각)
- [ ] stay/walk/run/sit/sitHi/lay 6개가 모두 제 클립으로 재생 (`[character] clips` 로그)
- [ ] 앉기·눕기 높이(`[character-calib]` 로그)가 지금과 같은지
- [ ] 반대 성별 사람 입장 시 추가 다운로드가 모델 1개뿐인지

## 2. [P0] 앱에서 다른 사람이 안 보인다 — `NET_ADAPTER: "mock"`

`config.js`

```js
NET_ADAPTER: "mock",
```

`mockAdapter.js`는 `BroadcastChannel`로 **같은 브라우저 탭끼리만** 주고받는다. 앱 WebView는 폰마다 따로라서 서로 안 보인다. 채팅, 방명록, 위치, 앉기 모두 혼자만 보인다.

`serverAdapter.js`의 `connect()`는 아직 `console.warn`만 찍는다. `addStroke` 등은 `throw`한다. `"server"`로 바꾸기만 하면 방명록을 쓸 때 에러가 난다.

할 일

- [ ] 기존 앱 소켓(socket.io)에 snowmap 전용 이벤트(`cafe:join`, `cafe:state`, `cafe:leave`, `cafe:chat`, `cafe:stroke`)를 붙인다. 계획 문서의 "3D용 서버를 새로 만들지 않는다"와 맞춘다.
- [ ] 서버가 방 정원, 자리 점유(6번), 입장·퇴장을 판정한다.
- [ ] `sendState`는 초당 10회(`NET_SEND_HZ`)다. 10명 방이면 서버가 초당 100개를 받아 90개씩 뿌린다. 서버에서 방 단위로 묶어 초당 5~10번 한 번에 보내는 방식을 고려한다.
- [ ] 브라우저 개발용으로 `mock`은 남기고, 앱에서 열 때는 쿼리(`?net=server`)나 `ReactNativeWebView` 유무로 자동 전환한다. 지금은 값을 손으로 바꿔야 해서 빌드 실수가 나기 쉽다.

## 4. [P0] WebView가 죽으면 흰 화면 — `TimerAniLab.jsx`

WebGL + 대용량 FBX 조합이라 메모리 부족으로 WebView 렌더 프로세스가 죽을 수 있다. 지금 `WebView`에 다음 처리가 없다.

- iOS: `onContentProcessDidTerminate` — 없으면 흰 화면에서 그대로 멈춘다.
- Android: `onRenderProcessGone` — 없으면 앱 전체가 같이 죽을 수 있다.

그 밖에

- `loadError`를 한 번 세팅하면 지우지 않는다. 다시 시도 버튼이 없다.
- 에러 박스에 `snowmapUrl` 전체를 보여 준다. URL에 `userId`, `displayName`, `avatarUrl`이 들어 있다. 출시 빌드에서는 숨긴다.
- WebView 안의 로딩(`#status`)과 RN `renderLoading`이 겹친다. RN 쪽은 HTML이 뜨는 순간 사라지고, 그 뒤 FBX 로딩은 웹 쪽 진행바가 맡는다. 진행 단계 문구가 한 번 끊겨 보인다.

할 일

- [ ] `onContentProcessDidTerminate={() => webRef.current?.reload()}`
- [ ] `onRenderProcessGone` → `key`를 바꿔 WebView를 새로 만들고, 반복되면 "저사양 모드로 다시 열기"를 보여 준다.
- [ ] 에러 화면에 다시 시도 버튼. 누르면 `loadError` 초기화 + `reload()`.
- [ ] 출시 빌드에서는 URL을 보여 주지 않는다.

- [ ] `sitHi`의 정규식이 `/sit/i`를 먼저 본다. 한 파일에 `sit`과 `sitHi`가 같이 있으면 `sitHi`가 `sit`을 잡는다. 정확 일치로 바꾸면 같이 해결된다.

## 6. [P1] 같은 자리에 두 명이 앉는다

`interactables.js`

```js
function setSeatOccupant(seatId, who) {
  const seat = seats.find((s) => s.id === seatId);
  if (!seat || seat === activeSeat) return false;   // 내가 앉은 자리면 무시
  seat.occupiedBy = who;
  return true;
}
```

- A와 B가 거의 동시에 같은 자리에 앉으면 둘 다 `occupiedBy`가 비어 있다고 보고 앉는다. 서로의 상태가 120ms 이상 늦게 도착하기 때문이다.
- 이미 내가 앉은 자리에 다른 사람 상태가 와도 무시만 한다. 결과적으로 두 캐릭터가 겹쳐 앉는다.
- `handleEntryAutoSeat`의 자동 착석도 같은 문제를 갖는다. 입장 직후는 원격 사람들 상태를 아직 못 받았을 수 있다.

할 일

- [ ] 서버가 자리 점유를 판정한다. `cafe:seat:claim` → 성공/실패 응답 후 앉기 애니메이션 시작.
- [ ] 자동 착석은 원격 상태를 처음 받은 뒤(또는 서버 응답 뒤) 한다.
- [ ] 자리 id는 `${메시 이름}#${슬롯 번호}`다. Blender에서 객체 이름을 바꾸거나 벤치 슬롯 수(`BENCH_SLOTS`)를 바꾸면, 옛 버전 클라이언트와 id가 어긋난다. 맵을 고칠 때 이름을 유지하고 버전을 같이 올린다 (15번 캐시 문제와 연결).

## 7. [P1] 캐릭터 그리기 비용

## 14. [P2] WebView 보안 옵션

`TimerAniLab.jsx`

```jsx
originWhitelist={['*']}
mixedContentMode="always"
```
