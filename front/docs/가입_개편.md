## 1. 목표 한 줄

**가입은 열고, 재학생 레이어(학교·학생 보드 등)만 학생증 인증 뒤에 둔다.**

---

## 2. 권한 표 (확정)

| 구분 | 쓸 수 있는 것 | 잠금 + 인증 유도 |
|------|----------------|------------------|
| **미인증** (성인·미제출·PENDING·REJECTED 포함해 앱 진입) | 전국 게시판, 개인 시간표(나이스 X), 타이머·스터디룸, 쪽지 | 우리학교, **개인·학교 우편**, 학교 게시판, 나이스·급식·등교·잔디, **학생 `board_type` 읽기·쓰기** 등 |
| **학생 인증 완료** | 위 + 학교 레이어 + 학생 전용 보드 읽기·쓰기 | — |

## 3. 가입·인증 흐름 (확정)

```text
[개편]
회원가입 (전 연령, 14세미만만 보호자)
  → 재학정보(학교·학년·반) 미입력 · 학생증 스킵 → 바로 앱(UNVERIFIED)
  → 우리학교/제한 화면 터치 시 「학생 인증이 필요해요」유도
  → 학생증 제출(이때 재학정보 입력) → PENDING → 승인 시 학교·학생보드 해금
```

### 에이전트 의견 — 「가입 때 학생증 없이 통과」

**동의. 이 흐름이 개편의 핵심에 맞다.**

- 지금처럼 가입 막바지에 학생증을 끼우면 PENDING 전면 Gate와 겹쳐 **유입이 다시 끊긴다.**
- 가입 = 계정 생성, 학생증 = **기능 업그레이드**로 나누면 성인·귀찮은 학생 모두 남고, 인증은 “우리학교가 필요할 때” 자연스럽게 유도된다.
- 주의: **서버에서도** 학교/학생보드 write는 `student_verified` 없으면 거절해야 한다. CTA만 믿으면 안 됨.
- REJECTED도 전면 차단보다 **앱 사용 + 재제출 진입점**이 전환에 유리하다.

## 4. 전체게시판 · 학생 보드

- UI: 게시판 탭 헤더에 **전체 | 학생** 세그먼트. 비활성(학생)은 회색, 활성 쪽에 슬라이딩 필 애니메이션.
- 데이터: **`board_type`**: `national` | `student` | `school`.  
  → 헤더 **학생**이면 `student`만 조회·작성. 미인증은 CTA + 서버 403.
- 학교 게시판(`school`)과 역할 분리 유지.
