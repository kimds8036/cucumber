📍 그룹 A — 위치/지오 기능
1. 거리 계산 | 2. Geofencing
문제점: 매 요청마다 DB에서 좌표 풀스캔 → 유저 늘수록 O(n) 폭발
솔루션:
MySQL → PostGIS(PostgreSQL) 마이그레이션 강력 추천
또는 MySQL 8.0 Spatial Index 활용 (현재 스택 유지 가능)
옵션장점단점MySQL Spatial Index현재 스택 유지기능 제한적PostGISST_DWithin, 인덱스 최강마이그레이션 필요Redis + Geosearch✅ 이미 Redis 있음! 초고속영구저장 불가
→ 추천: Redis GEOADD/GEORADIUS로 실시간 거리계산 캐싱
redisGEOADD school:posts 127.0276 37.4979 "post_id_123"
GEORADIUS school:posts 127.0276 37.4979 1 km ASC

🌿 그룹 B — 공부 잔디
문제점: 학교 전체 유저 집계 → 매번 GROUP BY 풀스캔
솔루션: Redis + 배치 처리 조합
실시간 기록 → Redis INCR/BITSET
집계(잔디 계산) → 배치 스케줄러 (1시간 or 자정)
결과 → MySQL 저장 + Redis 캐시
redis# 오늘 공부한 유저 비트맵
SETBIT school:1234:study:20260415 user_id 1
BITCOUNT school:1234:study:20260415  # 오늘 공부한 인원수

🔍 그룹 C — 실시간 인기 검색어 / 해시태그 / 인기게시글
문제점: 이게 가장 위험한 트래픽 — 모든 유저가 같은 데이터 반복 조회**
→ 이미 Redis 있으니까 Sorted Set이 정답
redis# 검색어 점수 누적
ZINCRBY trending:search 1 "수능"
ZREVRANGE trending:search 0 9 WITHSCORES  # 상위 10개

# 해시태그도 동일
ZINCRBY trending:hashtag 1 "#공부"

# 인기게시글 (좋아요+댓글 가중치)
ZINCRBY popular:posts:school:1234 3 "post_456"
캐시 TTL 전략:
데이터TTL갱신 주기실시간 인기검색어5분이벤트 드리븐인기 해시태그10분배치인기 게시글15분배치

전체 아키텍처 설계
[클라이언트]
     │
     ▼
[Nginx (로드밸런서)]
     │
  ┌──┴──┐
[API 서버] [API 서버]  ← Docker 수평 확장 (현재 컨테이너 복제)
     │
  ┌──┴──────────┐
  ▼             ▼
[Redis]       [MySQL]
  │
  ├─ Geo 캐시 (위치/Geofencing)
  ├─ Sorted Set (인기검색어/해시태그/게시글)
  ├─ Bitmap (공부잔디 실시간)
  └─ Session/일반캐시

[배치 스케줄러] → 잔디집계, 인기게시글 정산 (새벽 or 주기적)
