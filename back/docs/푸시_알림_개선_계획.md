# 푸시 알림 개선 계획 (iOS/Android 공통)

## 목적
- 앱이 **포그라운드/백그라운드/종료 상태**여도 사용자 상호작용(댓글, 좋아요, 친구요청, DM) 알림을 안정적으로 전달한다.
- 현재 정상 동작 중인 기능을 유지하면서, 운영 안정성/확장성을 높인다.

## 제안사항에 대한 의견

### 1) `fcm_tokens` 테이블 분리 (강력 추천)
- **동의**: `users.fcm_token` 단일 컬럼 방식은 멀티 디바이스(아이폰+아이패드, 재로그인, 앱 재설치)에서 토큰 충돌이 쉽게 발생한다.
- 권장 스키마(초안):
  - `id`, `user_id`, `token`(unique), `device_type`(ios/android), `app_version`, `is_active`, `last_used_at`, `created_at`, `updated_at`
- 기대효과:
  - 사용자당 다중 토큰 발송 가능
  - 토큰 무효화(`registration-token-not-registered`) 처리 자동화 용이
  - 플랫폼별 장애 분석이 쉬워짐

### 2) 푸시 발송 비동기화 (강력 추천)
- **동의**: 댓글/좋아요 API 응답 경로에서 직접 `await sendPush`를 하면 사용자 응답 지연 가능성이 크다.
- 권장:
  - 1차: DB 알림 저장 후 푸시 작업을 큐(Worker)로 위임
  - 2차: 재시도/지수백오프/실패코드별 토큰 정리 로직 추가
- 원칙:
  - 메인 비즈니스(댓글 등록 등)는 푸시 실패 때문에 롤백하지 않는다.

### 3) iOS `badge`, `mutable-content` 지원 (추천)
- **동의**: iOS 체감 품질에 큰 영향이 있다.
- 권장 payload:
  - `apns.payload.aps.badge`: 읽지 않은 알림 수(실시간 계산 또는 캐시값)
  - `apns.payload.aps["mutable-content"] = 1`: 향후 이미지/리치 알림 확장 대비
- 주의:
  - 배지 수 계산 쿼리 비용이 크면 캐시/비동기 집계 도입

### 4) 딥링크 전략 고정 (필수)
- **동의**: `targetScreen`만으로는 라우팅 정확도가 떨어진다.
- 권장 data 예시:
  - `{ "targetScreen": "PostDetail", "postId": "123", "commentId": "456", "type": "comment" }`
- 원칙:
  - 모든 알림 타입마다 최소 1개의 식별자(`postId`, `dmRoomId`, `friendRequestId` 등) 포함
  - 프론트 네비게이션 파라미터 스펙을 문서화해 서버/앱 동기화

## 단계별 실행안

### Phase A (기반 정리) — 완료 (`036`, `pushTokens.js`)
- `fcm_tokens` + `device_id` 멀티 디바이스
- `users.fcm_token` 제거
- 로그아웃 시 토큰 비활성화
- 알림 큐 멱등 처리 (`createNotificationOnce`, job 단계 플래그)

### Phase B (전송 파이프라인)
- 공통 `enqueuePushNotification()` 도입
- 상호작용 이벤트(댓글/좋아요/친구요청/DM)에서 큐 적재
- Worker에서 플랫폼별 payload 생성 및 발송

### Phase C (iOS/딥링크 고도화)
- `badge`, `mutable-content`, `sound` 정책 반영
- 알림 타입별 `data` 스키마 확정
- 앱 탭 이동 처리 통합 점검

### Phase D (운영 안정화)
- 실패코드 집계 대시보드(성공률, `third-party-auth-error`, `not-registered`)
- 무효 토큰 비활성화/정리 배치
- E2E 테스트 시나리오 정착

## 절대 준수 주의사항
- **기존에 정상 동작 중인 기능은 건드리지 않는다.**
- **디자인 요소(UI 스타일, 색상, 레이아웃, 컴포넌트 구조)는 절대 수정 금지.**
- 이번 개선은 **백엔드 푸시 파이프라인/알림 데이터 구조/로깅** 범위로 한정한다.
- 프론트 변경이 꼭 필요할 경우, 화면 디자인 변경 없이 라우팅/수신 처리 로직만 최소 수정한다.

## 완료 기준(Definition of Done)
- Android/iOS 모두에서 백그라운드/종료 상태 푸시 수신 확인
- 알림 탭 시 의도한 상세 화면으로 정확히 이동
- 사용자 설정 OFF 시 미발송 보장
- 푸시 실패가 메인 API 응답 속도/성공에 영향 주지 않음
- 실패코드 기반 토큰 정리 자동화 확인
