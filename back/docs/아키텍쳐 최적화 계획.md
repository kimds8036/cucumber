🌿 그룹 B — 공부 잔디
문제점: 학교 전체 유저 집계 → 매번 GROUP BY 풀스캔
솔루션: Redis + 배치 처리 조합
실시간 기록 → Redis INCR/BITSET
집계(잔디 계산) → 배치 스케줄러 (1시간 or 자정)
결과 → MySQL 저장 + Redis 캐시
redis# 오늘 공부한 유저 비트맵
SETBIT school:1234:study:20260415 user_id 1
BITCOUNT school:1234:study:20260415  # 오늘 공부한 인원수

🔍 그룹 C — 실시간 인기 검색어 / 해시태그 / 인기게시글
문제점: 이게 가장 위험한 트래픽 — 모든 유저가 같은 데이터 반복 조회**

백그라운드 작업 / 배치 처리 아키텍처 코드수정 계획
목표: 별도 워커 컨테이너 없이, 기존 Express 서버 컨테이너 안에서 `node-cron` 기반 배치를 안전하게 운영한다.

1) 기본 원칙 (현재 스택 최적안)
- 배치 실행 위치: `api`(Express) 컨테이너 내부
- 실행 방식: `app.js` 부팅 시 `jobs` 초기화 모듈 함께 로드
- 스케줄러: `node-cron`
- 저장소: Redis(중간 집계/락) + MySQL(최종 정산)
- 지금은 BullMQ/워커 분리 미도입 (트래픽/재시도 요구 커질 때 확장)

2) 코드 구조 제안
```txt
back/
  src/
    index.js
    jobs/
      index.js                 # 잡 등록 엔트리
      studyGrass.aggregate.js  # 잔디 집계
      trending.settle.js       # 인기 게시글/해시태그 정산
    services/
      batchLock.service.js     # Redis 분산락 유틸
      batchMetric.service.js   # 실행 시간/성공·실패 로깅
      batchRedis.service.js    # 배치용 Redis 연결 유틸
```

3) 실행 흐름
- `index.js`에서 서버 시작 후 `initJobs()` 호출
- `initJobs()`에서 cron 스케줄 등록
- 각 잡 시작 시 Redis 락 획득 (`SET lockKey value NX EX 300`)
- 락 획득 성공한 인스턴스만 실제 배치 수행
- 성공/실패 로그 및 소요시간 기록 후 락 해제

4) PM2 멀티 프로세스 주의사항 (중요)
- `pm2 start src/index.js --instances > 1`이면 같은 cron이 프로세스 수만큼 중복 실행될 수 있음
- 현재 권장:
  - 운영 기본값: 단일 프로세스(`--instances 1`)
  - 또는 환경변수 플래그 도입: `ENABLE_CRON=true`일 때만 스케줄러 기동
- 최소 안전장치: Redis 락으로 중복 실행 방지 (필수)
